# 嵌入式硬件控制实践

这一组天问 `.hd` 工程基于 STC8 平台，覆盖 GPIO 输出、按键输入、软件 PWM、LED 灯组、蜂鸣器、振动电机和音乐控制。图形化积木最终表达的仍是初始化、循环、分支、变量、函数和外设接口，适合作为从硬件现象进入程序结构的过渡。

## 板卡与外设

电路模型说明信号为何有效，控制程序决定信号何时变化。GPIO 实验用于确认端口方向和电平；按键引入输入与默认状态；PWM 把时间占空比转换为亮度或功率；UART 则让控制从单个引脚扩展到协议帧。

## 信号路径

```text
setup
├─ 板卡与 24 MHz 时钟初始化
├─ GPIO / UART 配置
└─ 变量与命令数组

loop
├─ 读取按键
├─ 更新状态或占空比
└─ 写 GPIO / 发送 UART 帧
```

## GPIO 与 PWM

呼吸灯使用 `duty` 表示占空时间，并用 `increment` 控制递增/递减方向。循环中分别输出高、低电平并延时，形成软件 PWM；达到边界后反向变化，亮度随平均导通时间渐变。

蜂鸣器和音乐工程同样通过端口翻转产生方波，但它们改变的是周期而不是占空比。不同微秒延时对应不同频率，按键分支调用不同的过程组合。转向灯工程开始使用自定义过程和参数，把重复的灯组时序从主循环中分离。

## 时序约束

- 依据原理图而不是积木名称确认端口和有效电平。
- 软件延时会占用 CPU，PWM、蜂鸣器和按键轮询同时运行时需要考虑阻塞。
- 按键没有天然稳定边沿，真实硬件需要消抖和按下/释放状态管理。
- 端口驱动电流有限，振动电机等负载必须通过合适的驱动级。

## 打开与检查

源资料记录的下载流程是选择 STC8 芯片、CH340 串口、目标程序与 24 MHz 频率，再触发下载并复位。仓库未提交驱动安装包、烧录器和 HEX 构建产物。复现时应先确认开发板原理图和当前 COM 口，再分别验证 GPIO、输入、定时和负载驱动。

## 程序结构

这些程序把状态、频率和占空比落实为循环、变量和 IO 时序。软件延时会阻塞其他任务，复杂工程需要定时器、中断或非阻塞状态机。
